# E2E framework comparison: Maestro vs Detox vs TesterArmy e2e

Research for [#109](https://github.com/Wojtas399/bh-cycling-app/issues/109) (map: #108). Gathered 2026-10-15 from primary sources: official docs, GitHub repos, releases, issues and npm.

Our stack (from `package.json`): `expo ~57.0.26`, `react-native 0.86.3` (New Architecture / bridgeless), `expo-dev-client ~57.0.19`, `expo-router ~57.0.24`, `@react-native-firebase/{app,auth,firestore,functions} ^24`.

## What TesterArmy e2e is

- An open-source (Apache-2.0) TypeScript **AI-assisted e2e framework for web and mobile** by TesterArmy, a commercial "agentic testing platform". Repo created 2026-07-22, ~10.7k stars, 30 contributors, releases several times a week. The README says: "in active development on the way to 1.0. APIs and config can still change between minor releases." ([README](https://github.com/tester-army/e2e))
- Tests are `.e2e.ts` files that mix deterministic, Playwright-style locators (`screen.getByTestId`, `expect(...).toBeVisible()`) with natural-language agent steps (`agent.act('sign in as ...')`, `agent.assert(...)`). An agent step that a later assertion verifies gets recorded and **replayed with no model calls** until the app changes. "Tests without agent steps need no model." You bring your own model: an API key, a subscription or a local model. ([README](https://github.com/tester-army/e2e), `docs/cache.mdx`)
- The mobile engine `@e2e-dev/mobile` (currently 0.12.x) is built on **Callstack's [agent-device](https://github.com/callstack/agent-device)** (created 2026-01, pinned at 0.21.28). It drives simulators and emulators from outside the app, so it is black-box and needs no native code in the app. ([docs/mobile.mdx](https://github.com/tester-army/e2e/blob/main/docs/mobile.mdx))
- The CLI sends telemetry by default. Opt out with `E2E_TELEMETRY_DISABLED=1`. ([README](https://github.com/tester-army/e2e))

## Facts the framework decision needs

1. **Detox is the risky option on our exact stack.** It has no official Expo support, and the Expo config plugin is stale (peer `expo ^53`). It is tested only up to RN 0.85.2. There is also a confirmed open bug: Android network sync ignores all `fetch` traffic on Expo SDK 56+, reported on RN 0.86.2, and the fix PR is unmerged. Its default branch has been quiet since June 2026. Its main advantage over the others, gray-box sync, is exactly the part that is broken for Expo 56+.
2. **Maestro is the mature, ecosystem-default choice.** React Native core uses it for its own New Architecture e2e. Expo's EAS Workflows e2e guide uses only Maestro. It needs no app changes and selects by `testID`. Its flakiness reports are generic driver issues, not stack-specific ones. It has a paid cloud ($250/device/mo) but runs free on GitHub Actions emulators and simulators.
3. **TesterArmy e2e is promising but pre-1.0, and it has two open bugs that hit our first smoke suite on iOS.** The `secureTextEntry` fill failure blocks email/password sign-in, and the false "covered" taps over an expo-router tab bar affect Home/Calendar navigation. Both were reported on RN 0.86.3 / Expo 57. It does have an Expo 57 / RN 0.86.3 example, an Android-on-Linux GitHub Actions recipe, TS tests and optional AI steps. Expect API churn between minors. Telemetry is on by default.
4. **All three are black-box except Detox**, so RN Firebase v24 is irrelevant to Maestro and TesterArmy. For Detox, native Firebase traffic and listeners add risk to idle sync.
5. **Build type:** Maestro and TesterArmy both work against a Release simulator `.app` / APK (EAS `e2e-test` profile: `simulator: true`, `buildType: apk`, no dev client). That avoids Metro in CI. TesterArmy documents dev-client launching too, but recommends Release for CI.
6. **Cheapest first CI target:** all three support Android on `ubuntu-latest` with KVM and an emulator. iOS needs a macOS runner for all three, unless you use Maestro Cloud or EAS Simulators (TesterArmy).
