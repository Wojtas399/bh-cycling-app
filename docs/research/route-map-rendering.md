# Research: map rendering options for the Route (Expo SDK 57)

Ticket: #133 (part of wayfinder map #131). Researched 2026-10-17.
This file records facts only. The decision belongs to #134.

Legend: **[verified]** means the fact was read in the cited primary source. **[unverified]** means it is inferred, comes from general knowledge, or the source was silent. Check these before relying on them.

## Project baseline (origin/main)

- `expo ~57.0.26`, `react-native 0.86.3`, New Architecture (the RN 0.82+ default), `expo-dev-client`, `react-native-svg 15.15.4`, `react-native-gesture-handler ~2.32`, `react-native-reanimated 4.5.1`.
- `app.config.ts`: `expo-build-properties` sets `ios.useFrameworks: 'static'`, `enableSceneSupport: true`, and `forceStaticLinking` for the RNFB pods. `userInterfaceStyle: 'automatic'` is set at the app level, so a map that "follows the system" can render light even though the UI is dark-only. Each option therefore needs an explicit dark setting.
- No map library is installed today, and there is no Google Maps API key in the config.

## Notes per option

### react-native-maps

- Apple Maps on iOS needs no key. Android is always Google Maps, which needs an API key restricted to the package name + SHA-1. The README warns that you "must sign up and create a billing account" [verified]. Staging and production package IDs differ (`…staging`), so the key restriction needs both IDs, or two keys [unverified detail].
- Dark mode on Android through `customMapStyle` JSON keeps map loads in the unlimited "Maps SDK" SKU. Using `googleMapId` moves them to "Dynamic Maps" (10k free per month) [verified].
- Android `liteMode` cannot do a dark color scheme. It can only take JSON styling [verified], so a dark lite map is possible with JSON styling.
- Expo issue #49323 (open): "Expo Go (SDK 57, Android): react-native-maps renders a blank/black map". This is Expo Go only. Dev-client impact [unverified].

### expo-maps

- Alpha on SDK 57: "This library is currently in alpha and will frequently experience breaking changes." [verified]
- SDK 58 docs state iOS 17+ [verified]. The SDK 57 docs don't state a minimum iOS [verified silent].
- Gaps for this use case: no fit-to-bounds, no snapshot, and no way to disable gestures on iOS [verified, by absence in the SDK 57 docs].

### MapLibre React Native

- v11 requires the New Architecture [verified], which matches this app.
- No Google or Apple dependency, and no key with OpenFreeMap. The dark look is fully controllable through the style JSON (it can be tuned to theme tokens).
- `StaticMapManager.createImage` gives a true static PNG for the inline view, rendered from `bounds` [verified]. The same style can then drive an interactive full-screen `Map`.
- Risks: a new iOS native dependency delivered through SPM plus a Podfile patch, under `useFrameworks: 'static'` and `forceStaticLinking` [unverified until a prebuild is tried]. OpenFreeMap has no SLA [verified], and paid tile hosts restrict commercial use on their free tiers [verified].

### react-native-svg line (tile-less)

- Zero new native code, no keys, no billing, no attribution, works in the existing build.
- Shows only the shape of the ride, with no streets, terrain, or place context. This is a product question for #134.
- Full-screen pan/zoom must be hand-built (pinch/pan with gesture-handler and reanimated). There is no basemap to reveal on zoom.
- Projection (Web Mercator or equirectangular), bounds, and simplification are pure functions. That gives a natural lib-level test seam (consistent with "no UI tests").

## Cross-cutting observations

- Every map-SDK option (1–3) adds a native module, so it needs a new dev-client build and a new EAS build. The Android Google path also needs a key provisioned as an EAS env var or secret.
- Point simplification (e.g. Douglas-Peucker) before rendering helps every option. Track size depends on the streams research.
- A wrapping `View` with `pointerEvents="none"` is a library-agnostic way to make any inline map non-interactive so it never steals scroll or pull-to-refresh [unverified per library].
